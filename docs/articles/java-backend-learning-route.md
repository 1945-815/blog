# 我的 Java 后端学习路线：学过什么，哪些还在实践

## 一、为什么学习这个技术

路线回顾的价值不是罗列工具，而是把课程、练习、项目和岗位要求连起来。我的背景是计算机科学与技术本科，求职方向为 Java 后端；路线图中的内容来自简历和学习计划，不能把“学过”直接等同于“熟练”。

## 二、技术原理

我把学习记录分成三层：能解释概念、能独立写出小型示例、能在项目上下文中说明取舍。Java 集合、Spring Boot、MyBatis、MySQL、Redis、消息队列、搜索和工作流是后端主线；RAG 属于应用探索，需要单独验证检索链路与模型接口。

## 三、核心代码实现

第一阶段整理 Java 语法、集合、异常、IO 与并发基础；第二阶段用 Spring Boot、MVC、MyBatis-Plus 和 MySQL 完成 CRUD、校验、分页与事务练习；之后再按业务问题学习 Redis、RabbitMQ、Elasticsearch、认证和 Activiti。微服务与 RAG 放在能讲清单体边界和检索流程之后。

每个主题保留一个可运行 Demo、关键问题和复盘记录。例如集合主题回答访问模式与对象相等性；缓存主题验证 TTL 和缓存失效；RAG 主题分别检查检索片段与生成回答。具体掌握程度应以仓库代码和本人实际操作为准。

**示例代码或流程：**

```java
public class User {
    private String name;
    public User(String name) { this.name = name; }
    public void sayHello() { System.out.println("Hello " + name); }
}
```

## 四、真实项目落地

这一阶段适合用用户或学生管理小程序练习类、对象和集合，再逐步添加数据库与接口。这里记录的是学习路径回顾，不表示 2023 年已经完成后来实习中的项目。

## 五、遇到的问题

不要把简历上的技术名词扩写成商业成果，也不要倒填并不存在的文章发布日期。阶段日期是路线图的规划顺序。能复现的命令、版本和结果应逐步补入仓库；未验证的部分明确标为示例。

## 六、优化方案

每个主题保留概念解释、最小示例和问题复盘三类证据；对尚未实际运行的部分标清状态，逐步补充版本、命令与结果。

## 七、个人思考

这条路线以 Java 后端工程能力为主，微服务和 AI 应用为延伸。后续文章按路线图逐篇补充，写作日期不替代真实发布时间。

## 延伸：面试问答

### 你如何证明学过的技术不是只看过教程？

给出可复现的 Demo、解释输入输出和关键取舍，并说明当前边界；没有实践证据的内容明确标注为学习笔记。

### 为什么博客不只写面试题？

文章同时留下问题背景、实现过程和复盘，面试时能从代码与决策展开，而非只背定义。

### RAG 是你的主方向吗？

目前是 Java 后端主线上的 AI 应用探索，重点是文档切分、召回、上下文组织与模型 API 集成，不宣称训练基础模型。
