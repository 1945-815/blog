# 文档检索服务的接口设计：上传、分类与分页

## 一、为什么学习这个技术

文档检索需要同时处理元数据维护与全文查询。接口需要定义文件限制、分类权限、异步索引状态和检索分页，不能把搜索引擎字段直接泄漏为客户端契约。

## 二、技术原理

上传接口负责边界校验和文件元数据登记；分类接口负责树形或层级规则；搜索接口组合关键词、分类、状态和分页；数据权限在服务端执行。搜索结果 DTO 与 ES 文档模型分离。

## 三、核心代码实现

先定义上传返回的文档 id 和处理状态，再定义按关键词和分类查询的请求 DTO。对页码、页大小设上限；排序字段按白名单映射。若索引更新异步进行，响应要说明可能存在的短暂检索延迟。

请求进入 Controller 后完成格式和大小校验，再由服务层保存元数据与文件引用，索引任务更新搜索读模型。查询时先做权限范围过滤，再构造 ES 查询，最后映射成精简响应。

### 文件和索引的生命周期

上传链路可以先校验扩展名、媒体类型和大小，再生成服务端文件标识；客户端文件名只作为展示元数据，不直接拼接到磁盘路径。文件存储成功与数据库登记之间可能部分失败，因此要定义临时文件清理或补偿任务。搜索索引异步更新时，文档详情查询和检索结果应分别说明状态，避免用户误以为“上传成功”就代表“已可检索”。

**示例代码或流程：**

```text
POST /documents          -> 返回文档 id 与处理状态
GET  /documents?category= -> 分类筛选与分页
GET  /documents/search?q=  -> 检索结果与来源摘要
```

## 四、真实项目落地

简历涉及文档发布、分类、分页与检索接口。文章以这些可公开职责为边界，用合成文档说明接口契约和索引延迟。

## 五、遇到的问题

不要把实际文件字节存入关系表的大字段而不评估需求；要限制文件类型、大小和路径。异常场景要避免已保存文件但无数据库记录，或反之。上传权限和下载权限分别校验。

## 六、优化方案

限制文件大小和类型，保存文件引用与索引状态；对上传成功但建索引失败提供可恢复路径。

## 七、个人思考

文档服务接口要定义元数据、文件生命周期、索引延迟和访问控制。字段设计应从业务契约出发，而不是照搬存储结构。

## 延伸：面试问答

### 上传接口应同步建好搜索索引吗？

取决于一致性要求和处理耗时；异步方案要公开处理状态并提供失败重试或重新索引。

### 分页接口为什么限制 size？

限制单次资源消耗，防止过大的响应和下游查询负担。

### 分类权限在检索哪里处理？

在服务端查询约束中执行，并确保过滤在返回前生效，不能依赖前端隐藏。
