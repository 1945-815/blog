# 旅游分享微服务课程流程：注册、攻略与内容检索

## 资料范围

本文归纳本地 0907—0911 旅游项目笔记和 0921 Canal、Swagger 学习笔记中的课程流程。`wolf2w-cloud` 是基于若依 Cloud 脚手架改造的课堂项目。本文是学习案例复盘，不能证明这是本人独立交付的企业项目，也不提供生产规模或性能数据；原笔记明确提醒不要把课堂项目原样包装成个人项目。

## 一、服务边界与注册调用链

课堂项目按业务拆分认证、会员、目的地、攻略、任务、消息和搜索等服务。Gateway 接收前端请求，认证服务处理注册登录，业务服务读写各自的数据；服务间通过 Feign 调用。任务服务触发周期工作，再通知业务服务执行统计。

~~~text
Vue 注册页
  -> Gateway /api/auth/register
  -> travel-auth 校验验证码与请求
  -> Feign 调用 travel-member 检查手机号并保存用户
  -> 返回注册结果
~~~

课堂笔记记录过重复手机号的空指针问题：会员服务返回失败时，认证端未先检查远程调用错误，就继续读取可能为 null 的 data。排查时应沿请求路径看 Controller、Feign 返回对象和失败分支。[Gateway 与 OpenFeign 的分工](/articles/gateway-openfeign-responsibilities)

## 二、验证码和登录状态

0907、0908 笔记记录消息服务把短信验证码存入 Redis，key 示例如 `verify_code:<phone>`，有效期 180 秒；注册请求由认证服务读取并校验。真实短信供应商配置不在本文重贴。

登录流程按手机号查用户、校验 BCrypt 密码，再签发 JWT。课程还将登录用户状态存入 Redis，笔记记录有效期 720 分钟。这是项目自有认证流程，不应误写为 Spring Security 自动完成了 JWT 登录。[Redis TTL 与验证码临时状态](/articles/redis-ttl)

## 三、目的地、攻略与互动

目的地按父子关系组织，页面可沿 `parent_id` 构造“中国—省份—城市”的导航。攻略主表 `ta_strategy` 保存标题、摘要、封面、目的地、状态和统计字段，`ta_strategy_content` 保存图文正文。课程笔记提到搜索以摘要为主，避免直接索引包含大量图片标签的正文。

分类挂在目的地之下，主题则是跨目的地的兴趣集合。攻略评论独立存储，再通过会员服务补充展示所需的用户资料。目的地页可以按阅读量取攻略前三；攻略首页读取任务生成的排行榜快照。分页、条件导航、主题推荐和评论各有自己的查询入口。

## 四、统计、缓存与周期任务

0914 笔记记录每篇攻略的阅读、回复、收藏、分享和点赞计数放在 Redis Hash 字段中；用户收藏关系使用 Set；每日点赞次数使用按用户和攻略区分的 String key，并在当天结束时过期。job 服务周期性调用攻略服务，把统计 Hash 快照覆盖写回 MySQL。

该流程将高频计数与数据库更新拆开，但本地笔记没有给出跨 Redis/MySQL 原子提交或生产可用性证明。超过点赞上限时，课程实现不会增加总点赞数；并发边界和独立 Lua 改写见 [Redis 日常配额案例](/articles/057-redis-daily-quota-lua) 与 [Redis 数据结构和 TTL](/articles/019-redis-types-ttl)。

课程排行榜是任务周期计算并保留的快照，页面查询最新一期；这和 Redis ZSet 实时排序是不同的设计问题。任务失败、重复执行和快照过期都需要单独制定策略。

## 五、从 MySQL 到搜索索引

0921 笔记记录 Canal 监听 `ta_strategy` 的 INSERT 事件，通过 RabbitMQ 通知搜索服务，再写入 Elasticsearch。发送端先把待确认消息放入 Redis ZSet，消费确认后移除；定时任务查找超时项并补发。课堂代码没有实现更新和删除，因此不能把它描述成通用、完整的 CDC 同步方案。

搜索查询可以先从 ES 取得命中 ID 与高亮片段，再由 MySQL 装配业务数据；关键词检索交给 ES，业务权威字段和展示权限仍由业务服务处理。[Canal、RabbitMQ 与 ES 同步](/articles/canal-mysql-to-elasticsearch) 与 [攻略搜索与高亮](/articles/064-elasticsearch-bool-highlight) 有进一步细节。

## 六、阅读课堂项目的检查顺序

1. 从页面请求 URL 和请求体确认前端实际发送的数据。
2. 从 Gateway 路由找到服务，再读 Controller、Service 和 Feign 接口。
3. 对照表结构确认字段归属，以及正文、评论、统计是否分开保存。
4. 检查失败返回、空数据和重复请求路径。
5. 对异步链路区分消息发送、消费确认和最终写入 ES 三个阶段。

课程记录里的组件版本属于当时的课堂依赖，升级时应重新核对各组件兼容关系。
