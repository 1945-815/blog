# 从实习项目中复盘接口开发、联调与问题定位

## 背景与问题

接口开发不止是写 Controller。字段契约、权限、持久化、异常响应、前后端联调和 Code Review 都会影响交付质量。复盘要从本人实际负责和参与的工作出发。

## 核心概念与设计

简历记录在团队指导下独立负责 2 个核心模块、累计完成 20+ RESTful API，并在测试联调阶段修复 10+ 问题；同时遵循 Git 分支与 Code Review 流程，使用 Cursor 辅助分析、接口开发和问题定位。文章只沿用这些已提供描述，不推导团队规模或业务指标。

## 实现与运行机制

把一次接口工作拆成需求确认、现有代码定位、DTO 与校验、业务服务实现、数据访问、错误映射、联调验证、提交审查和问题复盘。出现问题时保留请求 id、脱敏输入和复现步骤，再定位属于参数、权限、SQL、流程状态还是环境配置。

接口从请求映射、认证授权、参数绑定和校验进入业务服务，再到持久化或下游调用，最后形成响应。联调问题要比较接口契约与实际请求、服务日志和数据库结果；不能只凭前端页面现象直接归因。

## 问题与优化

不要公开公司的源代码、内部地址和生产数据。使用 AI 辅助时核对仓库约定、权限、异常和差异。复盘中的个人贡献应与团队成果区分，问题数量只能说明简历提供的测试阶段修复记录，不等于质量指标。

## 面试总结

### 如何讲清一个自己负责的接口？

按背景、请求契约、核心业务判断、数据变化、异常边界、联调问题和验证结果讲，明确自己实际完成的部分。

### 发现需求不清时怎么办？

先确认字段含义、状态规则、权限和错误响应，再通过接口契约或评审记录同步假设。

### Code Review 最关注什么？

业务正确性、权限与数据范围、异常处理、事务边界、SQL 条件、兼容性和可维护性。

## 总结

实习复盘应展示问题拆解和工程协作，而非堆砌技术名词。使用简历可证实的工作范围，补上自己真实能复现和讲解的具体例子。
